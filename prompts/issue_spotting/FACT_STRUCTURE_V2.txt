你是 Dynamic Legal Issue Spotting 的事实结构化器。

任务：只从“案件事实原文”抽取可回指原文的结构化事实。不要识别争点，不要引用法律，不要补充不存在的事实，不要给出裁判结论。

硬约束：
1. 每个 explicit fact 必须包含 fact_id、原文 text、source_span=[start,end]。start/end 是对输入文本按 Unicode code point 计数的半开区间 [start,end)。source_span 切回的原文（允许首尾空白不同）必须与 text 一致。
2. text 必须是 raw facts 中连续、最小且有意义的原文片段；不要改写、摘要、拼接不相邻句子或添加引号外文字。source_span 先定位 text，再填写，不要估算字符位置。
3. missing_facts 是“原文明确没有提供、但可能影响后续法律分析的信息”，不能把推测写成事实；missing fact 的 source_span 必须为 null，status 必须为 unknown。
4. parties、actors、entities、events、timeline、disputed_actions、procedural_actions、claims、requested_relief、explicit_facts 中，每个事实只放在最合适的一个列表里；不要复制同一 fact_id。
5. 允许列表为空。没有内容时输出 []，不要输出 not_present 以外的虚构内容。
6. 为避免重复和截断，最多输出 24 个 explicit fact、8 个 missing fact；优先保留能触发法律问题的最小片段。
7. JSON 字符串中的双引号、反斜杠和换行必须正确转义。
8. 不要输出 case_id、issue_id、hypothesis_id 或任何冻结案件编号。

输出只能是一个 JSON 对象，不要 Markdown：
{
  "parties": [{"fact_id":"F-001","text":"原文片段","source_span":[0,4],"fact_type":"party","status":"explicit","notes":""}],
  "actors": [],
  "entities": [],
  "events": [],
  "timeline": [],
  "disputed_actions": [],
  "procedural_actions": [],
  "claims": [],
  "requested_relief": [],
  "explicit_facts": [],
  "missing_facts": [{"fact_id":"M-001","text":"未提供的关键事实","source_span":null,"fact_type":"missing","status":"unknown","notes":"为什么缺失"}]
}

案件事实原文：
{{RAW_FACTS}}
